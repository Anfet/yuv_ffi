# RA-71 — Workflow VM-тестов
**Status:** BLOCKED · **Tier:** T3 · **Owner:** Luna · **Execution Mode:** FAST · **Review Tier:** T2 · **Depends On:** RA-70 · **Rejection Count:** 0

#### Problem / Goal
Вынести джобу `analyze-and-test-vm` из общего `ci.yml` в отдельный workflow с маршрутизацией по ключу ветки, независимо от чужих платформ.

#### Architect Decision
По соглашениям RA-70.
- Файл `.github/workflows/ci-vm.yml`, одна джоба, раннер `[self-hosted, Windows, X64]`, матрица Flutter 3.38.10 / 3.44.9. После checkout первым исполняемым шагом идёт `tool/ci/scope_guard.sh`, затем вызов `tool/ci/vm.ps1`; проверочная логика живёт в скрипте.
- Скрипт выполняет `flutter analyze lib test` и `flutter test` (теги `smoke` + `contract` — только после RA-60). Локально явно вызвать `tool/ci/drive.ps1` с `integration_test/native_app_runtime_smoke_test.dart` на Windows и зафиксировать оба условия вердикта: exit code 0 и строка `All tests passed`.
- Для карточки нужна ветка `all+vm/RA-71`: изменение общего `ci.yml` требует ключ `all`, а `ci-vm.yml` и `tool/ci/vm.ps1` — ключ `vm`. Брать ветку от актуальной `release/0.4.2`, работать в отдельном worktree и сохранить чужие изменения основной рабочей копии.
- `push` нового workflow фильтруется по `release/**`, `main`, `all/**` и токену `vm` в префиксе; `workflow_dispatch` доступен. Не добавлять `paths` или `paths-ignore`. Карта путей остаётся только в `tool/ci/scope_guard.sh`; её менять лишь при обнаруженном расхождении для VM-путей (`lib/**`, `test/**`, `pubspec.yaml`, `analysis_options.yaml`, `dart_test.yaml`).
- Формулировка «push только в `*.md` не запускает VM» действует для ветки `docs/**`, а «путь другой платформы» — для ветки с чужим ключом без `all`/`vm`. На `vm/**`, `all/**`, `release/**` и `main` push с одним Markdown тоже запускает workflow: веточный фильтр не смотрит на пути. `scope_guard.sh` проверяет уже запущенную джобу и не подавляет её запуск. Поэтому отрицательный контроль этой карточки — соответствие branch filters указанным веткам, а не отсутствие запуска при Markdown push в ветку реализации. RA-53 уже проверила отсутствие CI на ветке без ключа; изменение контракта CI не требуется.

#### Scope
`.github/workflows/ci-vm.yml`, `tool/ci/vm.*`, удаление джобы `analyze-and-test-vm` из `ci.yml`. Чужие workflow и скрипты не трогать.
