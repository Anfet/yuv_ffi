# RA-71 — Workflow VM-тестов
**Status:** TODO · **Tier:** T3 · **Execution Mode:** FAST · **Review Tier:** T2 · **Depends On:** RA-70 · **Rejection Count:** 0

#### Problem / Goal
Вынести джобу `analyze-and-test-vm` из общего `ci.yml` в отдельный workflow: он запускается только на свои пути и не зависит от чужих платформ.

#### Architect Decision
По соглашениям RA-70.
- Файл `.github/workflows/ci-vm.yml`, одна джоба, раннер `[self-hosted, Windows, X64]`, матрица Flutter 3.38.10 / 3.44.9.
- В YAML только checkout, выбор раннера и вызов `tool/ci/vm.ps1` (Linux — `.sh`). Логика — в скрипте.
- Скрипт выполняет: `flutter analyze lib test`; `flutter test` (теги `smoke` + `contract` после RA-60).
- Локальной проверкой явно вызвать `tool/ci/drive.ps1` на VM integration target и зафиксировать проверку обоих условий вердикта: exit code 0 и строка `All tests passed`.
- Маршрут по префиксу ветки (RA-53): `all/**` и ключ этого workflow; `release/**`/`main` — всегда. Пути платформы (`lib/**`, `test/**`, `pubspec.yaml`, `analysis_options.yaml`, `dart_test.yaml`) должны совпадать с картой `tool/ci/scope_guard.sh`; расхождение правится в карте, а не в workflow.

#### Scope
`.github/workflows/ci-vm.yml`, `tool/ci/vm.*`, удаление джобы `analyze-and-test-vm` из `ci.yml`. Чужие workflow и скрипты не трогать.

#### Definition of Done
- [ ] `tool/ci/vm` зелёный локально (лог в отчёте)
- [ ] Workflow зелёный на ветке карточки
- [ ] Push только в `*.md` и push в пути другой платформы его не запускают (ссылки на run или их отсутствие)
- [ ] Джоба `analyze-and-test-vm` удалена из `ci.yml`
