# RA-70 — Общие правила разделённого CI
**Status:** TODO · **Tier:** T2 · **Execution Mode:** STANDARD · **Review Tier:** T1 · **Depends On:** M1 · **Rejection Count:** 0

#### Problem / Goal
Сейчас один `ci.yml` с 11 джобами: любой push гоняет всё, одна красная джоба делает красным весь run, прогоны отменяют друг друга.

#### Architect Decision
- Одна платформа — один файл `.github/workflows/ci-<name>.yml` — одна джоба. `bindings-regeneration` остаётся в текущем `ci.yml` (решение Engineer); после RA-71…78 в `ci.yml` больше ничего нет.
- Каждая джоба выполняет один скрипт `tool/ci/<name>.ps1` (Windows/Mac через pwsh) или `.sh` (Linux). В YAML — только checkout, выбор раннера и вызов скрипта. Тот же скрипт исполнитель запускает локально до push: это и есть локальная проверка (пункт 1 ревью).
- Триггеры: `push`/`pull_request` с `paths` из RA-62 плюс `workflow_dispatch`; `concurrency: ci-<name>-${{ github.ref }}` с `cancel-in-progress: true`, кроме веток `release/*` — там прогон доходит до конца.
- Вердикт `flutter drive` — только через `tool/ci/drive` (exit 0 **и** `All tests passed`).
- RA-70 создаёт общую часть: `tool/ci/drive.ps1` (замена bash-версии для Windows/Mac), `tool/ci/_common.ps1` (Flutter/путь к native-сборке), описание соглашений в `AGENTS.md`. Сами workflow — в RA-71…78.
