# RA-72 — Workflow Windows native
**Status:** IN_PROGRESS · **Tier:** T2 · **Owner:** GPT-5.6 Terra · **Execution Mode:** STANDARD · **Review Tier:** T1 · **Depends On:** RA-70 · **Rejection Count:** 1

#### Problem / Goal
Вынести джобу `windows-native-smoke` из общего `ci.yml` в отдельный workflow: он запускается только на свои пути и не зависит от чужих платформ.

#### Architect Decision
По соглашениям RA-70.
- Файл `.github/workflows/ci-windows.yml`, одна джоба, раннер `[self-hosted, Windows, X64]`.
- В YAML только checkout, выбор раннера и вызов `tool/ci/windows.ps1` (Linux — `.sh`). Логика — в скрипте.
- Скрипт выполняет: native build (MSVC Release); `flutter test --tags probe,reference`; `flutter build windows` в example; app smoke и все `integration_test/*_native_test.dart` через `tool/ci/drive`. Поглощает прежнюю RA-23 (Windows в CI)..
- Локальной проверкой действительно вызвать `New-CiNativeBuild` из `tool/ci/_common.ps1` и сохранить успешный native build output в отчёте; одного parse/source check недостаточно.
- Маршрут по префиксу ветки (RA-53): `all/**` и ключ этого workflow; `release/**`/`main` — всегда. Пути платформы (`src/**`, `lib/src/yuv/impl/io/**`, `lib/src/functions/**`, `windows/**`, `test/probe/**`, `example/integration_test/**`) должны совпадать с картой `tool/ci/scope_guard.sh`; расхождение правится в карте, а не в workflow.

#### Scope
`.github/workflows/ci-windows.yml`, `tool/ci/windows.*`, удаление джобы `windows-native-smoke` из `ci.yml`. Чужие workflow и скрипты не трогать.
