# RA-55 — Заморозить релиз-кандидат
**Status:** TODO · **Tier:** T2 · **Execution Mode:** FAST · **Review Tier:** T1 · **Depends On:** RA-18, RA-19, RA-54 · **Rejection Count:** 0

#### Problem / Goal
Этап 1 заканчивается финальным кодом. Нужно зафиксировать SHA релиз-кандидата (далее РК), с которым дальше работают все проверки этапа 2, и убедиться локально, что код собирается и проходит тесты.

#### Architect Decision
1. На `origin/release/0.4.2` после слияния RA-18, RA-19, RA-54 выполнить локально (Windows, Flutter 3.44.9):
   - `flutter analyze` в корне и в `example/`;
   - `flutter test` в корне;
   - `flutter pub publish --dry-run` — 0 warnings;
   - в `README.md`, `CHANGELOG.md`, `example/README.md`, `assets/wasm/README.md` нет номеров задач и плейсхолдеров (`RA-`, `YUV-`, `AUD-`, `<!-- `, `TODO`, `draft`).
2. Записать в раздел «Состояние» `pre-release-todo.md`: SHA РК и дату.
3. **Замороженные пути** (код пакета): `lib/`, `src/`, `assets/`, `android/`, `ios/`, `macos/`, `linux/`, `windows/`, `example/lib/`, `example/pubspec.yaml`, `pubspec.yaml`, `README.md`, `CHANGELOG.md`, `example/README.md`, `LICENSE`. После заморозки они меняются только карточкой «Исправление: …» по дефекту, найденному на этапе 2; после неё RA-55 повторяется и даёт новый SHA РК.
4. Тесты, CI и инструменты (`test/`, `example/integration_test/`, `example/probe/`, `.github/`, `tool/`) на этапе 2 меняться могут: в замороженный код они не входят.

#### Scope
Только проверки и запись в `pre-release-todo.md`. Код не менять; если проверка не проходит — ARCHITECT_REQUIRED со списком ошибок.

#### Definition of Done
- [ ] Все четыре проверки из п.1 прошли; вывод — в отчёте
- [ ] SHA РК записан в «Состояние»
