# RA-53 — Маршрутизация CI по префиксу ветки
**Status:** TODO · **Tier:** T2 · **Execution Mode:** STANDARD · **Review Tier:** T1 · **Depends On:** RA-52 · **Rejection Count:** 0

#### Problem / Goal
После RA-52 карточная ветка получает CI только ручным `workflow_dispatch`: исполнитель должен помнить про запуск, а по списку run не видно, какие платформы проверены. Решение Engineer D-5: набор джоб определяется префиксом имени ветки и запускается автоматически на push.

#### Architect Decision
Правка `.github/workflows/ci.yml` и новый `tool/ci/scope_guard.sh`. Шаги джоб, кроме добавленного первого шага проверки, не менять. `workflow_dispatch -f jobs=…` из RA-52 остаётся запасным путём.

**Имя ветки:** `<ключи>/RA-xx`, где `<ключи>` — один ключ или несколько через `+`. Ключи — те же, что в RA-52, плюс `all`:

| Ключ | Джобы |
| --- | --- |
| `all` | все 11 |
| `vm` | `analyze-and-test-vm` (обе версии) |
| `bindings` | `bindings-regeneration` |
| `linux` | `linux-native-smoke` |
| `macos` | `macos-native-smoke` |
| `ios` | `ios-native-build` |
| `android` | `android-native-build` |
| `windows` | `windows-native-smoke` |
| `web` | `wasm-web-integration` |
| `example` | `example-analyze-and-build` (обе версии) |

Примеры: `web/RA-41`, `windows+android/RA-90`, `all/RA-95`.

**Триггеры.**
- `push`: `release/**`, `main` — полный прогон (как в RA-52); карточные ветки — фильтры `branches` на `all/**`, `<key>/**`, `<key>+*/**`, `*+<key>/**`, `*+<key>+*/**` для каждого ключа. Прочие ветки, в том числе `ra/**`, CI на push не запускают. Прежние `paths-ignore` сохраняются.
- Условие каждой джобы (без отдельного job-маршрутизатора — он стоял бы в очереди того же раннера): джоба выполняется, если событие не `push`/`workflow_dispatch` на карточной ветке, или ветка `release/**`/`main`, или токен ключа найден в префиксе. Токен ищется с разделителями, чтобы `win` не совпал с `windows`: в строке `format('+{0}', github.ref_name)` есть `+<key>/` или `+<key>+`; то же для `all`. Логику dispatch из RA-52 сохранить через `||`.
- `concurrency`: как в RA-52 (без отмены на `release/**`).

**Проверка префикса (`tool/ci/scope_guard.sh`, bash — есть на всех трёх типах раннеров).** Первый шаг каждой джобы на карточной ветке; на `release/**`, `main`, `pull_request` и dispatch пропускается. Checkout с `fetch-depth: 0`. Скрипт берёт `git diff --name-only $(git merge-base origin/release/0.4.2 HEAD) HEAD`, по карте вычисляет нужные ключи и падает с сообщением `scope: branch prefix '<prefix>' does not cover <keys> required by <path>`, если префикс их не покрывает (`all` покрывает всё). Карта в скрипте — единственный источник правды «путь → ключи»; первая совпавшая строка побеждает:

| Путь | Ключи |
| --- | --- |
| `*.md`, `doc/**`, `tasks/**` | — |
| `lib/src/functions/bindings/**`, `ffigen.yaml`, `src/include/**` | `all` |
| `.github/workflows/ci.yml` | `all` |
| `.github/workflows/ci-vm.yml` | `vm` |
| `.github/workflows/ci-windows.yml` | `windows` |
| `.github/workflows/ci-macos.yml` | `macos` |
| `.github/workflows/ci-ios.yml` | `ios` |
| `.github/workflows/ci-android.yml` | `android` |
| `.github/workflows/ci-linux.yml` | `linux` |
| `.github/workflows/ci-web.yml` | `web` |
| `.github/workflows/ci-example.yml` | `example` |
| `.github/workflows/**` | `all` |
| `tool/ci/drive.sh`, `tool/ci/scope_guard.sh` | `all` |
| `tool/ci/vm.*` | `vm` |
| `tool/ci/windows.*` | `windows` |
| `tool/ci/macos.*` | `macos` |
| `tool/ci/ios.*` | `ios` |
| `tool/ci/android.*` | `android` |
| `tool/ci/linux.*` | `linux` |

Неизвестный путь требует `all` — ошибка в сторону лишней проверки, а не пропуска.

Изменение общего `.github/workflows/ci.yml` или общей инфраструктуры `tool/ci/` требует `all`. Поэтому RA-71…78 используют префикс `all` при удалении своих джоб из `ci.yml`; после миграции изменения, ограниченные отдельным платформенным workflow и его скриптом, получают узкий платформенный префикс.

**Правила (текст для правил 1–2 в `pre-release-todo.md` уже внесён архитектором):** ветка карточки — `<ключи>/RA-xx`; префикс выбирает исполнитель по карте, оркестратор сверяет при запуске; коммит негативного контроля проверяется джобами префикса, откат пушится только после завершения контрольного прогона, иначе concurrency его отменит.

#### Scope
`.github/workflows/ci.yml` (триггеры, `if` джоб, первый шаг проверки, `fetch-depth`), `tool/ci/scope_guard.sh`. Ветка карточки — `all/RA-53` (правит `.github/**`). RA-70…78 не выполнять.
