# RA-52 — Выбор CI jobs на карточной ветке
**Status:** IN_PROGRESS · **Tier:** T2 · **Execution Mode:** STANDARD · **Review Tier:** T1 · **Owner:** Terra · **Depends On:** D-4 · **Rejection Count:** 0

#### Problem / Goal
Изменение на карточной ветке запускает весь монолитный `ci.yml`; jobs сериализуются на единственном Windows runner. Нужно запускать вручную только проверки текущей карточки, оставив полный прогон на release branch после merge.

#### Architect Decision (Engineer D-4, 29.09.2026)
- Менять только `.github/workflows/ci.yml`. Steps и реализация существующих jobs не меняются.
- Push в `ra/**` не запускает workflow. Карточные ветки запускают только выбранные jobs вручную: `vm`, `bindings`, `linux`, `macos`, `ios`, `android`, `windows`, `example`, `web`.
- Интерфейс запуска: `gh workflow run ci.yml --ref ra/RA-xx -f jobs=web`.
- Push в `release/**` после merge запускает полный CI. Полный run не отменяется новым запуском.
- Negative-control commits помечаются `[skip ci]` и запускается только нужная job.
- Если полный CI на release SHA красный после merge, оркестратор откатывает merge.

#### Definition of Done
- [ ] Workflow manual input принимает указанные job keys и запускает только выбранную job; остальные jobs имеют статус skipped.
- [ ] Push в `ra/**` сам по себе не запускает CI.
- [ ] Push в `release/**` запускает полный набор jobs; concurrency не отменяет ранее начатый полный прогон.
- [ ] Существующие job steps и команды остались без изменений.
- [ ] В отчёте перечислены локальные проверки, ручные run links и проверенный SHA.

#### Validation / Testing
- Сверить diff: изменён только `.github/workflows/ci.yml`; шаги jobs не менялись.
- На `ra/RA-52` выполнить `gh workflow run ci.yml --ref ra/RA-52 -f jobs=web`; проверить по GitHub API, что исполнилась только `wasm-web-integration`.
- Проверить полный workflow на release после merge и подтвердить, что ранее начатый run не отменён.
- Для negative-control использовать `[skip ci]` на commit и отдельный manual запуск только нужной job.
