# RA-57 — Полная проверка релиз-кандидата
**Status:** TODO · **Tier:** T2 · **Execution Mode:** FAST · **Review Tier:** T1 · **Depends On:** RA-53, RA-56, RA-70…75, RA-77, RA-78, RA-60…62 (RA-76 отложена; Linux проверяет `linux-native-smoke` в `ci.yml`) · **Rejection Count:** 0

#### Problem / Goal
После перестройки CI нужен один полный прогон всех платформенных workflow на коде релиз-кандидата. Это основная проверка релиза.

#### Architect Decision
1. Взять текущий SHA `release/0.4.2` после слияния всех карточек этапа 2. Проверить, что замороженные пути (RA-55) не отличаются от SHA РК: `git diff --stat <РК> <SHA> -- <замороженные пути>` пуст. Если не пуст — ARCHITECT_REQUIRED.
2. Убедиться, что на этом SHA завершились все платформенные workflow (vm, windows, macos, ios, android, linux, web, example) и `bindings` из `ci.yml`, все зелёные. Проверки новых workflow берутся из автоматических push runs на `release/0.4.2`; не использовать `workflow_dispatch` для workflow, ещё не попавшего в `main`, поскольку GitHub его не обнаружит. Если job не запустился на release push — зафиксировать причину и запустить через доступный после регистрации workflow механизм; не считать отсутствие run успехом.
3. Красный workflow → карточка «Исправление: …» (если дефект в коде — новая заморозка RA-55) или REWORK карточки, которая сломала тест/CI. Повторяется только упавший workflow, в конце — все на одном SHA.

#### Definition of Done
- [ ] Таблица: workflow → run → результат, все на одном SHA
- [ ] Пустой `git diff` замороженных путей относительно РК
