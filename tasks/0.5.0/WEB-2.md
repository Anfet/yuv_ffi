# WEB 2 — Web: оценка паритета WASM с native
**Status:** REVIEW · **Tier:** T2, Reviewer T1 · **Owner:** Codex · **Depends On:** — · **Probe:** windows
**Base SHA:** `8c3d88d1c6256a6f3e10f2e2db4e09d9f571c068`

#### Goal
Web — частичный WASM-бэкенд (README): набор операций сверяется по `YuvCapabilities`, проверяется только Chrome,
`flutter build web --wasm` не поддерживается. Общая проба на 1188 случаев уже запускается на Web и native против
одного `golden.json`; отдельная эталонная матрица конвертаций на Web содержит 119 случаев. Не установлено, какие
публичные пути остаются без сопоставимой проверки и где расходятся поддерживаемые браузеры. Задача — оценить разрыв,
а не закрыть его (D-21):

- сверить покрытие публичных операций и поддерживаемых форматов с native; общей пробой проверить конвертации,
  геометрию и краевые раскладки (padding, pixel stride, нечётные размеры), а за её пределами — вставку фрагмента и
  другие найденные непроверенные пути;
- подсчитать подтверждённые расхождения, неподдерживаемые и непроверенные сочетания с явным знаменателем;
- Safari и Firefox, `--wasm` — смоуком: запускается ли, что ломается;
- итог — перечень расхождений с оценкой объёма и рекомендация по каждому: чинить в 0.5.0, после релиза или описать
  в README.

Доведение до паритета — отдельные карточки по итогу оценки. Было WAIT-01.

Этап 7 (D-21), после принятых WEB 5 и APPLE 1.

#### Architect Decision
1. **Инвентаризация.** Составить таблицу публичных операций/форматных пар: `YuvOperation` и методы `YuvImage`,
   отдельно высокоуровневые пути `YuvFrameGeometry` и `applyPatch`. Для каждой строки указать native/Web
   `YuvCapabilities` (где применимо), тест/сценарий и статус: одинаково, расходится, не поддерживается, не проверено.
   Отдельно сверить фактические экспорты загруженного WASM с заявленными возможностями. Не считать 119 и 1188
   альтернативными объёмами одной матрицы.
2. **Сверка результата.** На одном SHA выполнить `windows.ps1` и `web.ps1`. Общая проба `probe_native_test.dart` /
   `probe_web_test.dart` сравнивается с одним `test/probe/golden.json` (1188 случаев, 22 сценария операций × 3 формата ×
   6 размеров × 3 раскладки); из лога сохранить `PROBE scope`, число несовпадений и SHA. Отдельная Web-матрица
   `reference_web_conversions_test.dart` даёт 119 эталонных случаев. Для непокрытых путей добавить минимальные
   сопоставимые случаи на native и Web: вставка I420/NV12/BGRA в допустимой позиции и у правого/нижнего края,
   один недопустимый ввод с проверкой неизменности результата; геометрия — поворот, crop и mirror на нечётном
   размере. Фиксировать байты, формат, размеры, revision и тип ошибки там, где они относятся к контракту.
   Диагностические случаи делать постоянными тестами только при найденном пробеле покрытия; тесты не подгонять под
   различие платформ.
3. **Браузеры.** Для Chrome, Firefox и Safari выполнить смоук обычной JavaScript-сборки: загрузка example,
   `YuvFfi.initialize()`, одна конвертация и одна геометрическая операция. Для `flutter build web --wasm` проверить
   сборку и запуск того же минимума; записать точный этап отказа (сборка, загрузка модуля или вызов), браузер и
   версию. Safari — на доступном Mac. Если браузер недоступен, записать это как непроверенное, не как отказ Web.
4. **Оценка.** Итог в `doc/web-parity.md`: таблица с числителем и знаменателем по проверенным случаям и по
   инвентарю публичных путей; подтверждённое расхождение отделить от отсутствия поддержки и отсутствия теста.
   Не экстраполировать долю ошибок выборки на все входы. На каждое расхождение — воспроизведение, влияние на
   пользователя и рекомендация. Рекомендовать исправление до 0.5.0, если ломается заявленный поддерживаемый
   сценарий или нарушается контракт данных/атомарности; остальные улучшения — отдельной карточкой после релиза,
   документируемые ограничения — в README. Изменение объёма релиза решает Engineer по этому перечню.

#### Scope
Оценка, минимальные тесты для пробелов покрытия, `doc/web-parity.md` и уточнение README по подтверждённым
ограничениям. Исправления реализации — отдельные карточки по итогу оценки.

#### Constraints
- Без изменений `src/`, сгенерированных bindings и WASM-артефактов ради диагностики.
- Не менять золотой эталон для согласования Web с native; считать ошибкой различие на общем случае.
- Отсутствие Safari/Firefox на доступной машине не подменять результатом Chrome.

- Вставка и геометрия вне матрицы проверены сопоставимыми сценариями либо явно отмечены как непроверенные с причиной.
- Для Chrome, Firefox, Safari и `--wasm` записан смоук или ограничение доступа; каждому найденному расхождению дана

#### Review
**REWORK** на `13419f8` (04.10.2026). Независимо воспроизведено: VM-срез общей пробы `PROBE_OPS=r90,cropped,meanRoi,swap` — `cases=216/1188`, PASS; тот же срез `probe_web_test.dart` через `drive.ps1` в Chrome — PASS; `yuv_image_patch_test.dart` и `yuv_frame_geometry_test.dart` — 23/23; `web_ownership_regression_web_test.dart` в Chrome — PASS. Инвентарь операций сверен с API: 12 `YuvOperation`, 42 пары, 2 неподдерживаемые; в `assets/wasm/yuv_ffi.js` есть все 11 символов ABI v1 (`flip` обслуживает оба отражения). Числа 1188/119 и вывод об отсутствии расхождений в выборке подтверждаются.

1. Случаи вне матрицы не сопоставимы между платформами (решение 2: «сопоставимые случаи… фиксировать байты»). Новый geometry-тест строит ожидание как `cropped(geometry.visibleSourceRect)` → `rotated` → `applyFlipHorizontal()`, то есть повторяет `YuvFrameGeometry.apply` дословно и не проверяет ни расчёт видимой области, ни байты; native и Web берут разные входы (`_uniqueRgba` против `i`), проверяется только BGRA. Нативная версия дублирует существующий тест «apply crops the visible source…», где прямоугольник задан явно. Web-проверка `applyPatch` проверяет только `any(byte == marker)`: не позицию, не неизменность остальных байтов и фрагмента, только край без допустимой внутренней позиции, отказ — только BGRA. Нужно: один общий случай с явными ожидаемыми байтами (5×3, I420 и BGRA; явный visible rect) на native и Web; на Web — точная побайтовая проверка вставки внутри и у края и один YUV-отказ (нечётная координата).
2. Нет итоговой таблицы решения 4 / DoD: числитель и знаменатель по инвентарю публичных путей и по браузерным целям со статусами «одинаково / расходится / не поддерживается / не проверено». В таблице операций нет колонки статуса; таблица публичных путей только описательная. Свести в одну таблицу (например: пары 40 одинаково / 0 расходится / 2 не поддерживается / 0 не проверено из 42; публичные пути N из M; браузеры 1 PASS, `--wasm` отказ, 2 не проверено из 4).
3. В отчёте не сказано, что `applyPatch` (`lib/src/yuv/shared/yuv_patch.dart`) и `YuvFrameGeometry.apply` — общий Dart-код поверх операций, уже покрытых golden-пробой на нечётных размерах (3×5, 33×17, 127×255) во всех форматах и раскладках. Это главное основание низкого риска расхождения по этим путям — записать его в `doc/web-parity.md`.
4. Новые проверки вставки и геометрии влиты в существующий `testWidgets('conversions and results own independent WASM buffers')` (`59bab3b`), чтобы не менять базу 63 случая в `tool/ci/web.ps1`. Тесты не подгоняются под гейт: вынести в отдельный `testWidgets` и обновить базу (`web_ownership_regression_web_test.dart` = 4, итог 64, строка в итоговом выводе).
5. Validation требует команды: для `--wasm` нет точной команды сборки и запуска (через `drive.sh`, не прямой `flutter drive`) и фрагмента лога. Добавить в отчёт.
