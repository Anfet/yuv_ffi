# WEB 4 — Кадры веб-камеры в исходном формате: вывод и рекомендация
**Status:** DONE · **Tier:** T2 · **Owner:** Reviewer · **Depends On:** WEB 6, WEB 7, WEB 8 · **Probe:** none

#### Goal
Web-источник камеры (`example/lib/camera/impl/yuv_camera_frame_source_web.dart`) читает кадр через
`MediaStreamTrackProcessor` и `VideoFrame.copyTo()` с `format: 'BGRA'` (запасной — `RGBA`): браузер переводит кадр в
RGB, потребитель получает `YuvImage.bgra`. Если `copyTo` без `format` отдаёт исходные I420/NV12, браузер не
конвертирует кадр, буфер в 2,7 раза меньше, а потребитель получает YUV. Стоит ли переходить — решает сумма трёх
подсистем, каждая замерена отдельно:

- захват — WEB 6: что отдаёт `copyTo` без `format`, стоимость `copyTo` в трёх вариантах;
- импорт — WEB 7: стоимость сборки `YuvImage` из I420/NV12 против нынешнего BGRA-импорта;
- показ — WEB 8: стоимость показа I420/NV12/BGRA (на Web шейдер выключен, WEB 1).

Задача — свести их в документ и дать рекомендацию. Изменение источника — отдельная карточка Architect по ней.

Пул `PAR-WEB`: WEB 6, WEB 7, WEB 8 параллельно → WEB 4. Завершается до этапа 6.

#### Architect Decision
1. **Суммы по одной машине.** Путь YUV = `copyTo` без `format` (WEB 6) + импорт I420 или NV12 — тот, что отдала
   камера (WEB 7) + показ того же формата (WEB 8). Путь BGRA = `copyTo` BGRA + импорт BGRA + показ BGRA. Слагаемые
   берутся с одной машины и одного Chrome; если для машины нет одного из слагаемых — сумма для неё не считается,
   это записывается.
2. **Критерий.** «Переходить», если на реальной камере исходный формат — `I420` или `NV12` и путь YUV по медиане не
   медленнее пути BGRA больше чем на 10 %. Иначе «не переходить сейчас» с условием, при котором вернуться (например,
   шейдер на Web после WEB 5).
3. **Документ** `doc/web-camera-yuv.md`: окружение (ОС, браузер и версия, камера, фактическое разрешение); факты
   кадра по каждой камере (WEB 6); таблица медиан по подсистемам и суммы путей; рекомендация по критерию 2 —
   «переходить» (формат, браузеры, что с запасным BGRA/RGBA-путём, набросок изменений источника) или «не
   переходить» (почему и когда вернуться); отдельной строкой — что изменится, если WEB 5 вернёт шейдер. Источники —
   спецификация WebCodecs (`VideoFrame.copyTo`, `PlaneLayout`, `VideoPixelFormat`) и MDN, ссылками. Firefox/Safari —
   одной строкой (там нет `MediaStreamTrackProcessor`, источник идёт через canvas). Числа — из отчётов WEB 6…8,
   новых замеров нет.
4. Вывод, который остаётся в силе, — одной строкой в `doc/perf-findings.md` (скорость Web раньше не мерилась).
