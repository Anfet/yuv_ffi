# FIX 6 — Документация 0.5.0 от опубликованной 0.2.4
**Status:** TODO · **Tier:** T2, Reviewer T1 · **Owner:** — · **Depends On:** — · **Probe:** none

**Base SHA:** `78eca6c6071004175431f58c27fc8101664d501b`

#### Goal

По D-28 пользователи pub.dev переходят на 0.5.0 с 0.2.4: версия 0.4.0 на pub.dev помечена retracted. README и
CHANGELOG сейчас описывают переход «from 0.4.0», а README:278 ссылается на невыпущенную 0.4.2. Документация релиза
должна быть точной для пользователя 0.2.4 и не содержать внутренних заметок.

#### Независимый вердикт (04.10.2026)

**Согласен с задачей.** README действительно ведёт с 0.4.0 и упоминает невыпущенную 0.4.2; CHANGELOG содержит
внутренний пункт про lockfile и повтор про Web-ассеты. `assets/wasm/README.md` отслеживается git, объявлен как asset
через каталог `assets/wasm/` и описывает себя как placeholder при наличии настоящих JS/WASM-файлов.
Уточнение к решению: 0.4.0 была опубликована и затем отозвана, поэтому 0.5.0 — следующий **доступный** выпуск для
пользователя 0.2.4, а не первый когда-либо опубликованный после неё. Таблица миграции должна показывать также смену
семантики `image.load(stream)` (мутация существующего объекта → новый объект из `YuvImage.decode(stream)`) и
`copy(blank: true)` (старая реализация переносила pixel stride в пустой кадр, `allocate` создаёт плотный);
одной компиляции сниппетов для этого мало.

#### Architect Decision

1. **README.md.**
   - Установка (строки 15–16) и «Migrating to 0.5.0» (строки 246–281): переход описан с 0.2.4. Отдельной фразой:
     0.4.0 была отозвана, и пользователю с lockfile 0.4.0 подходит та же таблица.
   - Каждую строку таблицы «Removed API → Current API» сверить с API 0.2.4 (`git show 0.2.4:lib/...`) и с текущим
     API. Строку, которой в 0.2.4 не было, пометить как «0.4.0» или убрать, если она пользователю 0.2.4 не нужна.
     Для `load(stream)` и `copy(blank: true)` явно объяснить разницу в мутации и layout, а не показывать их как
     равнозначную замену вызова.
   - После таблицы — короткий список изменений поведения, которые пользователь 0.2.4 встретит без ошибки компиляции.
     Источник — Breaking changes записей 0.4.0 и 0.5.0 в CHANGELOG: формат сериализации v2 (кадры 0.2.4 не читаются),
     I420 по умолчанию с `uvPixelStride: 1`, обязательный `YuvFfi.initialize()` перед `apply*` на native, `markDirty()`
     после прямой записи в плоскости, типизированные ошибки, исключённый Android `x86`, минимумы Dart/Flutter, упаковка
     `planes:` по умолчанию. Только факты, уже записанные в CHANGELOG; без новых обещаний.
   - Строка 278: «cannot be decoded by 0.4.2» → «by 0.5.0» (формат v2 действует с 0.4.0).
   - Сниппеты README компилируются (способ — Validation).
2. **CHANGELOG.md, запись 0.5.0.**
   - Вводная строка: следующий доступный релиз на pub.dev после 0.2.4; 0.4.0 была опубликована и отозвана, и её
     изменения (запись 0.4.0 ниже) входят в переход с 0.2.4.
   - Убрать внутренние пункты: выравнивание lockfile example (замечание ревью FIX 4) и повтор «Rebuilt the Web JS/WASM
     assets» (он есть и в Highlights, и в Changes — оставить один). Каждый оставшийся пункт проверить: изменение
     заметно пользователю пакета.
   - «Moving from a 0.4.0 lockfile» → раздел обновления: с 0.2.4 (`yuv_ffi: ^0.5.0`, затем таблица README и Breaking
     changes 0.4.0 и 0.5.0) и с lockfile 0.4.0.
3. **CHANGELOG.md, запись 0.4.0.** Заголовок `## 0.4.0 (retracted)` и одна строка о том, что версия отозвана с pub.dev и
   заменена 0.5.0. Ссылку на несуществующий раздел README «Migrating from `0.2.4`» исправить на «Migrating to 0.5.0».
   Остальной текст записи и более старые записи не менять.
4. **example/README.md** — сверить утверждения о платформах и API с текущим кодом; правка только при расхождении.
5. **`assets/wasm/README.md` удалить.** Текст устарел («placeholder»), а `pubspec.yaml` объявляет весь каталог
   `assets/wasm/`, поэтому файл попадает в asset bundle каждого приложения. Сборка WASM описана в README и
   `tool/wasm/README.md`. Перед удалением `rg` — никто не ссылается на файл; `pubspec.yaml` не менять.
