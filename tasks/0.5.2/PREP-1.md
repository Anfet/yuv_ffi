## Goal

Подготовить проверяемую карту разделения `yuv_ffi 0.5.2` и `yuv_camera 0.0.1`, по которой Architect сможет расписать перенос без потери тестового покрытия и скрытой зависимости YUV-примера от камеры.

## Architect Decision

1. Результат — `doc/camera-extraction.md`: таблицы «исходный путь → назначение → причина → проверка». Для каждого файла/группы назвать действие: оставить, перенести, разделить. Группировка допустима только для одинакового действия; смешанные тесты описывать по отдельности.
2. Граница пакетов и целевые версии — раздел «Цель и границы цикла» в `todo.md`. Презентер, геометрия и шейдер остаются в YUV; камера зависит от публичного API YUV; ML Kit остаётся в примере камеры. Не проектировать новые API и платформенные плагины ради переноса.
3. Инвентаризация охватывает `example/lib/`, `example/test/`, `example/integration_test/`, `example/benchmark/` при наличии, `example/tool/`, assets, зависимости pubspec и платформенные конфигурации примера, а также ссылающиеся на них тесты корня, `tool/ci/`, workflows и документацию. Не читать пути из `.ignore`, generated bindings или build.
4. Для каждого смешанного сценария перечислить сохраняемые утверждения и их целевой тест. Отдельно разобрать device-check, редактор, ML Kit-конвертацию, camera capture, desktop smoke, Web camera source, iOS BGRA import и сравнения способов импорта. Операционные probe/reference и тесты синтетического потока остаются у YUV.
5. Для каждого перемещаемого integration target записать текущие вызывающие скрипты, конфигурацию runner/device и будущую команду. Не обещать поддержку платформы по наличию исходника: сохранять текущие ограничения, включая непроверенную iOS-ориентацию и Web-браузеры. Подсчёты и завершающие сообщения CI описать как изменения, необходимые при переносе.
6. Описать порядок: подготовить новый пакет и перенести проверки → подтвердить их в новом окружении → удалить исходный камерный код/зависимости и переключить CI. Зафиксировать связь версий, локальную подмену зависимости до публикации и отдельного потребителя для проверки пары; основной пример YUV камерой не нагружать.
7. Предложить расположение нового checkout и размещение `camera_desktop`. A1: desktop-провайдер подключается и регистрируется приложением, пакет камеры использует `camera_platform_interface`. Если анализ текущей регистрации обнаружит препятствие, A2: описать конкретную необходимую адаптацию и её проверку в последующей карточке, без пробных правок кода. Соседний проект в этой задаче не создавать и не менять.
