## AUD-17 — Проверить ARMv7 runtime или обосновать исключение

- Статус: TODO; исполнитель: GPT-6 Sol High; rejection count: 1; commits `ca9b43391e833432a1f2c27b7681d92363d227e7`, `c178da092ee12f29ae38597d4073953cb3b0ebd1`.
- Факт: `android-emulator-runner@v2` поддерживает system-image architecture только `x86`, `x86_64` и `arm64-v8a`, поэтому `arch: armeabi-v7a` был бы неподдерживаемым и не доказывал бы runtime. Android Emulator API 30 x86/x86_64 image штатно рекламирует ARMv7 ABI и запускает ARM binaries через native bridge; Android также документирует, что часть ARMv7 binaries на таких image может не работать. Это делает ARM-only smoke значимым failure gate, а не compile-only проверкой.
- Действие: job `android-armv7-runtime` собирает target `native_app_runtime_smoke_test.dart` с `--target-platform android-arm`, до запуска требует единственный APK ABI `armeabi-v7a` и `libyuv_ffi.so`, затем запускает этот APK на API 30 `google_apis` x86_64 image. Скрипт записывает `ro.product.cpu.abilist`, требует в нём `armeabi-v7a` и выполняет no-skip `flutter drive` против prebuilt ARM-only APK.
- Локальная проверка: `flutter build apk --debug --target=integration_test/native_app_runtime_smoke_test.dart --target-platform android-arm` успешно завершился за 43.8 s; YAML workflow распарсен, staged `git diff --check` и commit check прошли.
