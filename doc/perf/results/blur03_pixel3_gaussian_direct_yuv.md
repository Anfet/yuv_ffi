# BLUR-03 — прямой 2D Gaussian по Y и Y/U/V

Статус: REVIEW. Pixel 3 `8B1X11QLW`, Android 12, Release/AOT. База
`c115d78868226218d9c9ae60ee31403e49cc2234`. Production C и ABI не
менялись: обе сборки кандидата выполнены из отдельного detached worktree.
Для воспроизведения сохранены [Y-only patch](blur03_gaussian_yonly.patch) и
[Y/U/V patch](blur03_gaussian_yuv.patch) к `src/yuv/abi/yuv_gaussian_blur_v1.c`
этой базы. Каждый patch проходит `git apply --check` на исходной базе;
патчи являются артефактами эксперимента, не изменением production.

## Контракт измерения

В каждом случае вызван один и тот же публичный
`applyGaussianBlur(radius: 10, sigma: 10)`. RGB — исходная реализация:
2D Gaussian в RGB с обратной записью YUV. Кандидат Y-only сворачивает Y
непосредственно 2D ядром `r=10, sigma=10` и копирует UV. Кандидат Y/U/V
дополнительно сворачивает U и V раздельно 2D ядром `r=5, sigma=5`.
Оба ядра используют `exp(-(dx²+dy²)/(2σ²))`, нормализацию суммой весов,
округление к ближайшему байту и clamp на краях. Разделимых проходов здесь нет.
Внутренний цикл кандидата читает плоскости напрямую и делает clamp каждого
sample; RGB baseline использует ring декодированных строк и отдельный быстрый
путь для внутренних пикселей. Поэтому разность времени характеризует этот
прямой 2D YUV кандидат целиком, а не отдельно стоимость RGB-конверсий.

Кандидат специализирован только для полного tight packed NV12 при указанных
radius/sigma. Иные валидные дескрипторы, ROI и настройки вызывают исходную
реализацию. Общая проверка ABI, формата, геометрии и alias выполняется до
записи; веса Y выделяются до записи, поэтому ошибки валидации/выделения не
оставляют частично записанный результат. Для production ещё нужны отдельные
проверки padding/stride, odd geometry, ROI, BGRA и alias именно выбранной
реализации; эти замеры не принимают перенос.

Источник — `tool/bench/fixtures/blur_reference_1477x1065.png`,
SHA-256 `7c36de007e221a60403fb2a17f5bbc40c8f410a8f1e74fe67ff851503825c600`.
Второй вход: crop `(0, 163, 1476, 738)` и linear resize до 720×360.
Пакетный `YuvImage.nv21` конструктор выбрал packed `Y + UV` и публичный
`format=nv12`; это порядок подготовленного пакетом входа, не утверждение
о raw CameraX буфере. SHA-256 входа: 1477×1065
`09ab1306d279f6b79bcc77dced485bc2d0691cf823aad82c0b5b1ad6f041cc78`;
720×360 `1fada775114bc0f90a9fb1338acdfd302c281331598400c328fde897106a289e`.

PNG decode, подготовка Y+UV и `source.copy()` выполнены вне таймера.
Таймер охватывает полный публичный вызов, включая Dart transport и native
result copy. На каждый вариант/размер — 2 warmup и 7 отдельных samples.

Все девять checksum каждого входа/варианта внутри прогона совпали. PNG
экспортированы из фактического последнего измеренного результата после
остановки таймера, декодированы как 1477×1065:

- [RGB](blur03_gaussian_rgb.png), PNG SHA-256 `632a0acd8ff831357a54fcc482a6f8813c4f8e354498cf604f533e524430b907`;
- [Y-only](blur03_gaussian_yonly.png), `de6d132a5f618daf5508ec28a496625b9758f0934a1f0bf6fb9ababc2e07940c`;
- [Y/U/V](blur03_gaussian_yuv.png), `175562ad90c462ec536938711031b8628051892903271e069465e1883f7ab9ea`.

На этом кадре Y/U/V визуально близок к RGB, Y-only заметно оставляет резкие
цветовые границы. Средняя абсолютная разница RGB–Y/U/V по декодированным RGB
каналам 0.466 байта, RGB–Y-only 2.581 байта; максимум по RGB–Y/U/V каналам
5/4/6 байт. Это наблюдение одного кадра, не критерий для смены семантики.
Старый byte-exact RGB oracle к новому YUV-результату неприменим.

Отказ от RGB при прежней 2D сложности даёт ≥25% на обоих размерах:
полный Y/U/V вариант экономит 489.608/77.857 ms, но сам остаётся
938.257/147.677 ms. Ускорение возможно, но для камерного пути этого
замера недостаточно, чтобы принять production перенос. Будущую выгоду
разделимого ядра этот эксперимент не измеряет.

Полные JSONL/logcat находятся в `blur03_raw/{rgb,yonly,yuv}/` и
`blur03_control/yuv/`. Package SHA у всех трёх сборок —
`c115d78868226218d9c9ae60ee31403e49cc2234`, записанный `HEAD:src`
`d4e9e54fd92a53ce204ecc36f0031c8db3e2085c` относится к базовому
дереву. Фактический SHA-256 скомпилированного C-файла:
RGB `13d6de53e807ce4252b3c9860b0424f365a7395354a4914c34dfcf15f9529a4f`,

Оба candidate patch проверены `git apply --check`, C прошёл
`clang -fsyntax-only`, Dart runner — `flutter analyze lib/main.dart`.

Для повторения взять чистую базу `c115d78` в двух отдельных worktree и
применить к ним по одному соответствующему patch через `git apply`.
RGB измеряется из корня пакета; кандидат — из своего worktree:

```powershell
./tool/bench/run_blur_pixel3.ps1 -Operation gaussian -PackageSourcePath D:\.projects\yuv_ffi -Variant rgb
./tool/bench/run_blur_pixel3.ps1 -Operation gaussian -PackageSourcePath <isolated-worktree> -Variant yonly
./tool/bench/run_blur_pixel3.ps1 -Operation gaussian -PackageSourcePath <isolated-worktree> -Variant yuv
```

Для двух последних команд использовать разные worktree с соответствующим
patch. Изображение после каждого запуска находится в
`/sdcard/Android/data/com.yuvffi.bench.blur_runner/files/blur03_gaussian_<variant>.png`
и копируется `adb pull`. Эти команды не применяют patch к production.
