# Текущая стоимость конвертаций ABI v1 на Windows

Замерено 26 сентября 2026 на коммите `3564f5ff4cf9d04755fd6d080d52933e2ae89593` после принятия OPT-14. Один и тот же Windows x64 Flutter 3.44.9 / Dart 3.12.2 Release/AOT executable, собранный из этого SHA; нативная библиотека собрана вместе с приложением MSVC Release. Размер каждого входа — 1920×1080, layout tight, данные детерминированы. Power Plan и affinity не менялись.

Время — **полный публичный Dart вызов**. Создание входного изображения и SHA-256 результата находятся вне таймера; внутри могут быть Dart staging, выделение destination, FFI, native kernel и копирование результата. Для `RGBA.*` внутри вызова находится `YuvImage.fromRgbaBytes`, включая создание целевого изображения. Для совпадающих форматов `to*` возвращает независимую глубокую копию без `yuv_convert_v1`.

Каждый прогон запускал отдельный процесс с одной калибровкой, прогревом и 30 образцами для конверсий или 50 для копий. Все 24 строки имеют `status=OK`; SHA результата для каждого направления совпал между прогонами. [Raw CSV](conversion_windows_1080p_raw.csv) сохраняет образцы, разброс, SHA, размер и версии; имя машины в нём заменено на `local-windows`. У `I420 → NV12` в первом прогоне p95=23.163 мс при медиане 10.292 мс, поэтому для приоритета используем оба прогона, а не выброс.

По чтению кода основной кандидат — `yuv_convert_to_bgra`: выбор packed/I420/NV12 и вычисление адресов повторяются внутри пиксельного цикла. `yuv_convert_relayout` проходит chroma посэмплово. `yuv_convert_from_packed` уже считает блоками 2×2, поэтому его ускорение требует отдельного измерения и сохранения точной арифметики. Доля Dart staging/копирования в этих временах пока не измерена; разницу между публичным временем и временем C нельзя приписывать одному только ядру. Следующий шаг — изолировать эту долю, затем оптимизировать по одной C-функции.
