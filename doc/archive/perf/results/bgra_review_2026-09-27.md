# Независимое ревью BGRA-00…04, 27.09.2026

Проверена ветка `release/0.4.2` на HEAD `ebe3c64` до этого ревью. Production C/Dart код не менялся. Итог: **BGRA-00 и BGRA-03 — COMPLETE; BGRA-01, BGRA-02 и BGRA-04 — TODO**. Windows-оптимизации остаются в коде; TODO означает недостающий критерий измерения, а не обнаруженную регрессию результата.

## Причина расхождения Pixel 3

Устройство: `adb devices -l` → `8B1X11QLW device`, Pixel 3. Команда из `example/`:

```powershell
flutter drive --driver=test_driver/integration_test.dart --target=integration_test/bgra0102_native_kernel_pixel3_test.dart -d 8B1X11QLW --profile
```

Одинаковые исходники и тестовый файл; profile APK пересобран перед каждым запуском. Вход 720×360, 5 прогревов, 30 замеров каждого вызова, SHA-256 результата `1638d13f0aab5308d972d00d7611f1cdb928de29bafc4c06907e0793ac3ecf55`:

| Состояние устройства во время прогона | NV12→BGRA `toBgraBytes()` | I420→BGRA `toBgraBytes()` |
| --- | ---: | ---: |
| `mWakefulness=Awake`, `mScreenOn=true`, keyguard снят | 10,561876 мс | 11,383439 мс |
| Экран выключен через `adb shell input keyevent 26`; `mWakefulness=Dozing`, `mScreenOn=false` до и во время теста | 43,170786 мс | 45,881359 мс |

Прогон с выключенным экраном выполнен с `--no-pub`, остальные параметры команды те же. Он завершился `All tests passed`; контрольная сумма совпала. После опыта экран включён, keyguard снят через `adb shell wm dismiss-keyguard`; `mWakefulness=Awake`, `mScreenOn=true`, `mDreamingLockscreen=false` проверены. Тепловой статус после первого прогона был 0; причина четырёхкратного различия связана с состоянием экрана/сна, а не с изменением алгоритма. Это причинный эксперимент с одним устройством и одинаковым кодом; точный механизм выбора частот CPU отдельно не измерялся.

Отдельный profile-прогон `bgra00_stage_breakdown_pixel3_test.dart` при включённом экране дал медианы `toBgraBytes()` NV12 10,918335 мс, I420 11,275366 мс; `toBgra()` NV12 12,099481 мс, I420 12,068543 мс. Все четыре результата имели тот же SHA-256 и `All tests passed`. Таким образом, ~11–12 мс из отчётов воспроизводятся, а ранее зафиксированные ~43–50 мс также объяснимы выключенным экраном. Старые прогоны не содержат `mScreenOn` лога, поэтому их точное состояние экрана задним числом не доказано.

## Проверка кода и Windows результата

- `src/yuv/abi/yuv_convert_v1.c`: NV12/I420 dispatch вынесен перед пиксельным циклом; chroma-компоненты переиспользуются на пару Y, generic stride и хвост нечётной ширины сохранены. Формула BT.601 и byte-exact oracle покрываются ранее запущенными C тестами и текущими Android прогонами. C тесты в этом проходе не перезапускались. Android тест измеряет полный публичный вызов, не отдельное C-ядро.
- `lib/src/yuv/impl/io/abi/yuv_abi_v1_runner.dart`: `convert()` вызывает `_isTightLayout(destinationLayout)` и использует `malloc` только для плотных плоскостей; для row padding/pixel gaps остаётся обнуление. `flutter test test/bgra03_dest_alloc_test.dart test/bgra04_copy_out_test.dart test/yuv_bgra_pixel_gap_test.dart test/abi_status_mapping_test.dart -r compact` — 49/49 passed. Тесты включают canary, отказ аллокатора и независимость копии от native памяти.
- `doc/archive/perf/results/bgra05_final_windows_1080p_raw.csv`: самостоятельно сгруппированы три раунда `OK` по исходнику и паре, пересчитана медиана медиан. NV12 43,1865→30,0045 мс (−30,5%), I420 43,7135→30,5430 мс (−30,1%); SHA-256 внутри каждой группы стабилен. Это Windows AOT `toBgraBytes()` 1080p, не результат Pixel 3 и не отдельный `toBgra()`.

## Решение по карточкам

| ID | Вердикт | Причина и следующее действие |
| --- | --- | --- |
| BGRA-00 | COMPLETE | Windows стадийная разбивка и Pixel 3 полный вызов есть. Причина 4-кратного расхождения независимо воспроизведена: экран включён/выключен. Pixel 3 тест не даёт отдельные стадии; их доли в отчёте относятся к Windows. |
| BGRA-01 | TODO | NV12 код и Windows ускорение корректны, текущий Pixel 3 вызов byte-exact. По общему правилу `todo.md` нужен baseline/candidate на одинаковом Pixel 3 в одинаковом AOT режиме при включённом экране, затем 1080p контроль. Нынешний файл явно не сравнивает версии и не измеряет C-ядро отдельно. |
| BGRA-02 | TODO | То же для I420; дополнительно проверить отсутствие регрессии NV12 в до/после прогоне на устройстве. |
| BGRA-03 | COMPLETE | Исправление padded/gapped дефекта и сохранение tight malloc fast path подтверждены адресными тестами и чтением пути аллокации. Итоговый профиль всей цепочки остаётся в BGRA-05. |
| BGRA-04 | TODO | На Windows альтернатива bulk-copy не дала устойчивого выигрыша, production-код не менялся. Pixel 3 тест повторяет текущий полный `toBgraBytes()`, не сравнивает реализации copy-out; ARM/AOT вывод об отсутствии выигрыша пока не подтверждён. Нужен изолированный безопасный copy-out A/B замер с проверкой памяти и lifetime либо ограниченный Windows-вывод. |

Условия следующего Android замера: записывать `mWakefulness`, `mScreenOn` и состояние keyguard непосредственно перед запуском и во время измерения; использовать один вход, checksum, сборку и режим для baseline/candidate. Состояние экрана следует включить в сами машинно читаемые результаты, чтобы не повторить прежнюю неопределённость.
