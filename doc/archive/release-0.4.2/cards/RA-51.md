#### Architect Decision
1. В `test/probe/probe_copy_sync_test.dart` сохранить проверку полного совпадения имён, байтов и `golden.json`. Root-only список для `2ef5e15` содержит ровно восемь имён: `operation_coverage_test.dart`, `probe_copy_sync_test.dart`, `probe_performance_test.dart`, `probe_runner.dart`, `probe_runner_test.dart`, `probe_scenarios.dart`, `release_probe_core_test.dart`, `windows_release_package_provenance_contract_test.dart`. Первые семь уже указаны в тесте; добавить только восьмое. После фильтрации должны сравниваться все 28 файлов с каждой стороны без ручной подгонки ожидаемого числа.
2. В `.gitignore` явно разрешить четыре отслеживаемых `doc/archive/release-0.4.2/ra25-pixel3/raw/{arm64,armv7}.{stdout,stderr}.log`. В `example/integration_test/wasm_swap_nv_atomicity_web_test.dart` локально подавить `deprecated_member_use` для намеренной проверки legacy API.
3. Ветка `ra/RA-51` создаётся от чистого `release/0.4.2` (`2ef5e15`); её коммит содержит только три файла реализации из пунктов 1–2 и эту карточку. Проверить локально `flutter analyze lib test`, `flutter test test/probe/probe_copy_sync_test.dart`, `cd example && flutter analyze`, `flutter pub publish --dry-run` (0 warnings), затем один commit/push и CI на новом SHA.
4. После слияния RA-51 в `release/0.4.2` создать отдельные карточные ветки RA-25 и RA-26 от обновлённой release. Исполнитель RA-25 переносит свой `test/probe/run_release_android_test.dart` и одновременно добавляет его девятым root-only именем в своей ветке; повторяет copy-sync проверку. Исполнитель RA-26 переносит только свои ещё незакоммиченные изменения: Windows provenance test уже есть в исходном SHA. Согласно решению Engineer D-3, после переноса RA-25/26 остаются замороженными до фазы 6; новые Pixel- и benchmark-прогоны до неё не начинать.
